这个页面就是一个静态文件。没有服务器，没有数据库，没有统计，也没有 Cookie 提示条 —— 因为根本没有 Cookie 需要提示。Astro 在构建时把 Markdown 和组件渲染成 HTML，产物发到 GitHub Pages。你访问它时发出的网络请求，只有字体、图片和页面本身。

这是有意的选择，不是极简主义的姿态。我的工作就是测量软件假设了什么是安全的，而我能以自己名义放到互联网上的、最诚实的东西，就是一个文件目录。

## 像素画有规矩

像素画只能按整数倍缩放。在 2.23 倍下，有的画布像素占两个屏幕像素，旁边的占三个，清脆的图就糊了。所以这里每一个 sprite 都带着从 manifest 生成的显式宽高，乘的是整数；另有一个检查脚本，会在五种视口宽度下遍历构建产物，只要发现哪个 sprite 是非整数倍，就让构建失败。

中文字体是同一个问题。Ark Pixel 画在 12px 的网格上，只有在 12 的整数倍时才清晰，所以中文路由树里每一处像素字号都被吸附到 12px 的台阶上。同一个脚本会在标题落到 19.5px 时报错。

## 那只三角龙

页脚那只三角龙是我自己画的。把它弄进站里反而是整个过程中最难的一步：我手上只有一张被重新采样过的截图，方块因此发生了漂移 —— 同一个方块在画面这头量出来是 20 像素，到那头就是 23 像素。

所有自动求真实格宽的办法都失败了。对强边缘做相位拟合，锁到了 11.66，恰好是真实周期的一半。最小化复原误差根本没有极小值，因为网格越细，复原得越像。按凹陷的显著性排序，20.0 和 32.5 反而排在正确答案前面。

真正管用的是去量那些格数能直接从画上数出来的特征。腿宽 95 像素，间隔 68 像素，每 163 像素重复一次 —— 四格、三格、七格。背脊的阶梯在两个方向上都是 20 到 25 像素，那就是一格。于是得到 23.6，整只动物是 45 乘 26。

这里面有一个关于「没有极小值的目标函数」的教训，我觉得它不止适用于恐龙。

## 邮箱地址

我的邮箱不在 HTML 里。它以 XOR 加 base64 的形式存着，构建时从不还原成明文，所以它也不在这个仓库里。点一下按钮，浏览器把它解出来并复制到你的剪贴板。

这挡得住批量抓取 —— 那些爬虫只读标记，不执行 JavaScript。它挡不住你，也不打算挡：任何人读一个很短的文件就能在一秒内反推出来。检查脚本每次构建都会去点那个按钮，并在地址于点击前就出现在页面里时报错。
